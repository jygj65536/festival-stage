# 🎪 페스티벌 미니앱 — 프로젝트 로드맵 & 실행 계획서

> 앱인토스 입점 | 2인 팀 | v1.2 · 2026.05

---

**📌 이 문서는?**
국내 페스티벌 정보 미니앱을 앱인토스에 입점하기까지의 전체 로드맵과 기획 · 디자인 · 개발 · 운영 각 영역의 태스크 및 고려사항을 정리한 실행 계획 초안입니다.

| 역할 | 담당 |
|------|------|
| A | 기획 + 디자인 겸임 |
| B | 개발 담당 (AI 코딩 도구 적극 활용, 개발 경험 초보) |

> 🤖 **AI 코딩 도구 활용 전제**
> 이 문서의 개발 태스크는 Cursor / Claude / GitHub Copilot 등 AI 코딩 도구를 적극 활용하는 것을 전제로 작성되었습니다.
> 코드를 처음부터 혼자 짜는 것보다 **'AI에게 무엇을 시킬지'를 정확히 아는 것**이 더 중요합니다.

## 0. 전체 로드맵 한눈에 보기

아이디어 → 콘솔 등록 → 개발 → 검수 → 출시 → 성장까지 5개 Phase로 구성합니다.

| Phase | 기간 (예상) | 핵심 목표 | 완료 기준 |
|-------|------------|-----------|-----------|
| **Phase 0** 준비 & 셋업 | 1주 | 방향 확정 · 환경 구축 | 앱 이름 확정 · 콘솔 등록 · 개발 환경 세팅 |
| **Phase 1** 기획 & 디자인 | 2~3주 | 서비스 설계 · UI 완성 | 피그마 최종본 · 정보구조(IA) 확정 |
| **Phase 2** 개발 & 연동 | 5~7주 | 기능 구현 · SDK 연동 | 로컬 테스트 통과 · 번들 업로드 완료 |
| **Phase 3** 검수 & 출시 | 1~2주 | 앱인토스 4단계 검수 | 검수 승인 · 라이브 오픈 |
| **Phase 4** 운영 & 성장 | 출시 후 지속 | DAU 확보 · 수익화 | MAU 1,000 · 수익화 모델 가동 |

> ⏱ **총 예상 소요 기간: 약 10~14주** (2인 팀 · AI 코딩 도구 활용 기준)
> 파트타임이나 데이터 수집 병목이 발생하면 최대 +3~4주 여유를 고려하세요.
> 개발 경험이 적을수록 '설계'와 'AI 프롬프트 작성' 시간이 코딩보다 더 걸립니다. Phase 2에 여유를 충분히 잡으세요.

## Phase 0 · 1주차 — 준비 & 셋업

> 방향 확정 · 콘솔 등록 · 개발 환경 구축

가장 짧지만 이후 모든 Phase의 방향을 결정하는 단계입니다. 특히 **appName은 한 번 등록하면 절대 바꿀 수 없으니**, 앱 이름을 확정하기 전까지 콘솔 등록을 서두르지 마세요.

### 태스크

| 영역 | 태스크 | 담당 | 설명 & 고려사항 | 💡 팁 / ⚠️ 리스크 |
|------|--------|------|----------------|-------------------|
| 공통 | 앱 이름 & 브랜드 방향 최종 확정 | 둘 다 | 줄임 어감 테스트 · 영문명 15자 이내 · appName 스킴 후보 정리 (intoss://xxx 형식) · 스킴 중복 여부 확인 | ⚠️ appName 등록 후 절대 변경 불가 |

| 기획 | 참고 서비스 벤치마크 | 기획/디자인 | 라이브네이션, 인터파크, 소셜편의점 UX 분석. 타임테이블 UI 패턴 스크린샷 수집. 차별점 정리 | 💡 잘 만든 앱을 많이 보는 게 디자인 공부의 지름길입니다. |
| 공통 | 협업 방식 & 툴 합의 | 둘 다 | 노션(문서/태스크) · 피그마(디자인) · GitHub(코드) · 주간 싱크 요일 확정 | 💡 노션 무료 플랜으로 충분합니다. |

### ✅ 이것만은 꼭

1. **앱 이름** (줄임 어감 포함) — appName은 등록 후 변경 불가
2. **MVP 범위** — 기능 몇 개로 시작할지
3. **사업자 등록 여부** — 수익화 / 토스 로그인 필요 여부 판단
4. **페스티벌 데이터를 어떻게 모을지** — 수동 입력? 주최사 협력? 크롤링?

### 🚫 토스 UX 제약 — 검수 반려 주요 원인

디자인 단계에서 미리 체크하지 않으면 검수에서 반드시 반려됩니다.

- 외부 앱 설치 유도 버튼 또는 배너 금지
- 외부 결제창 이동 금지 (토스페이로만 결제해야 함)
- 자사 웹사이트로 단순 유도하는 구조 금지
- 토스 공통 내비게이션 바 디자인 임의 수정 금지
- 허용되지 않은 3rd-party 분석/로깅 툴 사용 금지

## Phase 2 · 4~10주차 — 개발 & SDK 연동

> 기능 구현 · AI 코딩 · 테스트 · 번들 업로드

개발 경험이 적을수록 이 구간이 가장 오래 걸립니다. AI 코딩 도구를 최대한 활용하되, **'무엇을 만들어야 하는지'를 먼저 명확히 정의해두는 것**이 AI 활용의 핵심입니다.

### AI 코딩 도구 활용 전략

| 단계 | 방법 | 예시 |
|------|------|------|
| 1단계 — 맥락 주기 | 프로젝트 배경을 먼저 설명 | "나는 앱인토스 WebView 미니앱을 만들고 있어. React + TypeScript야." |
| 2단계 — 구체적 요청 | 원하는 결과물을 상세하게 | "페스티벌 리스트를 카드 형태로 보여주는 컴포넌트 만들어줘. 데이터는 이 JSON 형식이야." |
| 3단계 — 에러 해결 | 에러 전체를 그대로 붙여넣기 | "이 에러 왜 나는지, 어떻게 고치는지 설명해줘" |

> 추천 도구: **Cursor** (코드 편집기 + AI 통합) / **Claude** (복잡한 설계·설명) / **GitHub Copilot** (자동완성)

### 추천 기술 스택 (초보 최적화)

| 영역 | 추천 선택 | 이유 |
|------|-----------|------|
| 프레임워크 | React + TypeScript | create-ait-app 기본 제공. AI가 가장 잘 도와주는 스택. TypeScript 사용 강력 권장 |
| 상태 관리 | Zustand or React Query | 가볍고 직관적. Redux는 2인 팀에 과함 |

| 백엔드 / DB | Supabase | PostgreSQL + 인증 + 스토리지 올인원. 코드 없이 테이블 생성. 무료 티어로 MVP 충분 |
| 배포 (프론트) | Vercel | GitHub 연결 후 push하면 자동 배포. 설정 거의 없음 |
| 지도 | 순수 SVG + React | 라이브러리 없이 AI가 코드 짜주기 쉬움 |
| AI 코딩 도구 | Cursor (주력) | 편집기 + AI 통합. '이 코드 고쳐줘' 한 줄로 해결 |
| 협업·문서 | 노션 + 피그마 | 무료, 직관적, AI와 연동 가능 |

### 💡 개발 초보 팀에게 주는 실용 팁

- **처음엔 기능 2개로 시작하세요.** 완성이 우선입니다 — '탐색 + 타임테이블'만으로도 가치 있습니다.
- **Cursor를 쓰면** '이 에러 고쳐줘' 한 줄로 대부분 해결됩니다. 에러 무서워하지 마세요.
- **AI가 짜준 코드는 반드시 샌드박스에서 돌려보세요.** 동작 확인 후 다음 단계로.
- **모르는 개념은** AI에게 '초보자에게 설명하듯 알려줘'라고 하면 됩니다.
- **앱인토스 개발자 커뮤니티** (techchat-apps-in-toss.toss.im)에 가입하면 빠른 QA 해결 가능.
- **지인 20~30명에게 먼저 테스트** 요청하세요. 실제 유저 반응이 가장 좋은 피드백입니다.
- **디자인은 토스 앱빌더 먼저** — TDS 컴포넌트 쓰면 검수에도 유리합니다.
- **페스티벌 주최사에 먼저 연락** — 데이터 제공 + 협찬 가능성 동시에 열립니다.
